# 评审指南

## 概述

本指南提供**测试分析报告评审**（阶段 3）的详细规则、评分标准。

**适用范围**：阶段 3 - 测试分析报告评审  
**评审对象**：`02-test-analysis-report.md`、`02-test-points.json`

---

## 一、评审维度及权重

| 评审维度 | 权重 | 通过线 | 评审重点 |
|----------|------|--------|----------|
| 完整性 | 30% | ≥80 分 | 功能模块/API 覆盖、IBO 分析完整、报告结构完整 |
| 准确性 | 30% | ≥80 分 | IBO 特征识别、测试方法适配、API 信息准确 |
| 测试点评审（三方比对） | 25% | 100 分（必须完全一致） | 模块数、用例总数、级别分布、模块级用例数一致性 |
| 测试点质量 | 25% | ≥75 分 | 可执行性、可判定性、具体明确、级别划分 |
| 兼容性 | 15% | ≥80 分 | 兼容性矩阵、DFX 测试、安全测试、自动化分析 |

**通过标准**：总体≥80 分 且 各维度均达标 且 三方比对 100% 一致

---

## 二、评审检查清单

### 2.1 完整性检查清单

| 检查项 | 说明 |
|--------|------|
| 功能模块覆盖 | 所有功能模块（F-01, F-02, ...）都有测试分析 |
| API 覆盖 | 所有 API 接口都有测试点覆盖 |
| IBO 分析完整 | 每个模块都有 IBO 三维分析 |
| 报告结构完整 | 报告四部分（1.1~4.4）章节齐全 |
| 兼容性测试 | 3.2 章节包含设备款型表、API 版本表、交叉组合矩阵 |
| DFX 测试 | 3.3 章节包含稳定性/性能/功耗/UX 四个维度 |
| 安全测试 | 3.4 章节包含病毒扫描/漏洞扫描/敏感信息三个维度 |
| 自动化分析 | 3.5 章节包含可行性分析表、覆盖率统计 |

### 2.2 准确性检查清单

| 检查项 | 说明 |
|--------|------|
| IBO 输入分析 | 准确识别参数类型（String/数值/对象/枚举等） |
| IBO 行为分析 | 准确识别行为特征（状态转换/异步/队列等） |
| IBO 输出分析 | 准确识别返回值类型 |
| 测试方法适配 | 测试方法与 IBO 特征匹配 |
| API 信息准确 | 测试点覆盖的 API 名称与需求解析一致 |
| 级别划分 | 测试点级别符合 L0-L3 判定规则 |
| 优先级合理 | 模块优先级（P0/P1/P2）划分合理 |

### 2.3 测试点质量检查清单

| 检查项 | 说明 |
|--------|------|
| 黑盒功能视角 | 测试点描述使用功能视角，无"调用"、"访问"、"返回"等 API 层面词汇 |
| 描述具体 | 测试点描述具体，无模糊词汇 |
| 可执行 | 测试步骤清晰，测试人员可理解执行 |
| 可判定 | 验证点具体明确，有明确判定标准 |
| 无模糊描述 | 无"功能执行正确，结果符合预期"等模糊描述 |
| API 标注 | 每个测试点标注了覆盖的 API（在测试点属性中，不在描述中） |
| 编号规范 | 测试点编号规范（模块 ID+ 序号） |

### 2.4 兼容性检查清单

| 检查项 | 说明 |
|--------|------|
| 兼容性矩阵 | 4 款型×4API 版本矩阵完整，必测/选测标识清晰 |
| DFX 测试 | 稳定性/性能/功耗/UX 四个维度均有测试策略 |
| 安全测试 | 病毒扫描/开源漏洞/敏感信息三个维度均有测试策略 |
| 自动化分析 | 自动化可行性评估 + 覆盖率计算完整 |

## 三、评分标准

### 3.1 完整性评分（100 分）

| 评审项 | 分值 | 扣分规则 |
|--------|------|----------|
| 功能模块覆盖 | 30 分 | 每遗漏 1 个模块扣 10 分 |
| API 覆盖 | 30 分 | 每遗漏 1 个 API 扣 5 分 |
| IBO 分析完整 | 20 分 | 每缺少一维分析扣 5 分 |
| 报告结构完整 | 20 分 | 每缺少一章扣 5 分 |

### 3.2 准确性评分（100 分）

| 评审项 | 分值 | 扣分规则 |
|--------|------|----------|
| IBO 分析准确 | 30 分 | 每处特征识别错误扣 5 分 |
| 测试方法适配 | 25 分 | 每处测试方法不匹配扣 5 分 |
| API 信息准确 | 25 分 | 每处 API 名称错误扣 5 分 |
| 优先级正确 | 20 分 | 优先级划分不合理每处扣 5 分 |

### 3.3 测试点评审（三方比对）（100 分）

| 评审项 | 分值 | 扣分规则 |
|--------|------|----------|
| 模块数一致性 | 30 分 | 不一致直接扣 30 分 |
| 用例总数一致性 | 25 分 | 不一致直接扣 25 分 |
| 级别分布一致性 | 25 分 | 每级不一致扣 8 分 |
| 模块级用例数一致性 | 20 分 | 每模块不一致扣 5 分 |

**否决规则**：任何一项校验失败，测试点评审直接判定为**不通过**。

### 3.4 测试点质量评分（100 分）

| 评审项 | 分值 | 扣分规则 |
|--------|------|----------|
| 测试点覆盖率 | 30 分 | 每遗漏 1 个测试点扣 5 分 |
| 黑盒描述规范 | 25 分 | 每处使用 API 视角描述扣 5 分 |
| 测试点描述 | 20 分 | 每处模糊词汇扣 3 分 |
| 验证点质量 | 25 分 | 每处验证点模糊扣 5 分 |

**黑盒功能视角判定规则**：
- ✅ 正确：「验证屏幕常亮功能是否正常工作」、「检查能否成功获取设备信息」
- ❌ 错误：「调用 enableWakeLock 方法」、「访问 deviceInfo 属性」、「返回值是否为 true」

### 3.5 兼容性评分（100 分）

| 评审项 | 分值 | 扣分规则 |
|--------|------|----------|
| 兼容性矩阵 | 30 分 | 矩阵不完整扣 15 分 |
| DFX 测试 | 25 分 | 每缺少一维度扣 8 分 |
| 安全测试 | 25 分 | 每缺少一维度扣 8 分 |
| 自动化分析 | 20 分 | 分析不完整扣 10 分 |

## 四、通过标准

| 维度 | 通过分数线 |
|------|------------|
| 完整性 | ≥ 80 分 |
| 准确性 | ≥ 80 分 |
| **测试点评审（三方比对）** | **100 分（必须完全一致）** |
| 测试点质量 | ≥ 75 分 |
| 兼容性 | ≥ 80 分 |
| **总体** | **≥ 80 分** 且各维度均达标 |

**否决规则**：三方比对有任何不一致，测试点评审判定为不通过，需重新生成测试分析报告。

## 五、测试点级别判定规则

| 模块优先级 | 测试类型 | 级别 |
|-----------|---------|------|
| P0 (核心功能) | 正常流程 | L0 |
| P0 (核心功能) | 异常/边界流程 | L1 |
| P1 (重要功能) | 正常流程 | L1 |
| P1 (重要功能) | 异常/边界流程 | L2 |
| P2 (辅助功能) | 正常流程 | L2 |
| P2 (辅助功能) | 异常/边界流程 | L3 |

## 七、评审结论

| 评审结论 | 条件 |
|---------|------|
| **通过** | 总体≥80 分 且 各维度均达标 且 三方比对 100% 一致 |
