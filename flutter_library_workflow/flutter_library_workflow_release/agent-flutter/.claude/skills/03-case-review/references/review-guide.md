# 测试用例评审指南

## 概述

本指南提供**测试用例评审**（阶段 5）的详细规则、评分标准和输出模板。

**适用范围**：阶段 5 - 测试用例评审  
**评审对象**：`04-test-cases.md`、`04-test-cases.json`、`02-test-points.json`

---

## 一、评审维度及权重

| 评审维度 | 权重 | 通过线 | 评审重点 |
|----------|------|--------|----------|
| 覆盖率 | 35% | ≥85 分 | 功能模块覆盖、测试点覆盖、API 覆盖、测试类型覆盖 |
| 可执行性 | 30% | ≥80 分 | 步骤清晰性、操作可行性、前置/后置条件明确 |
| 可判定性 | 20% | ≥80 分 | 预期结果明确、验证点具体、无歧义 |
| 规范性 | 15% | ≥75 分 | 测试标题规范、测试步骤规范、API 备注规范、用例 ID 规范 |

**通过标准**：总体≥80 分 且 各维度均达标

---

## 二、评审检查清单

### 2.1 覆盖率检查清单

| 检查项 | 说明 |
|--------|------|
| 功能模块覆盖 | 所有功能模块（F-01, F-02, ...）都有测试用例 |
| 测试点覆盖 | 测试分析报告中的所有测试点都有用例对应 |
| API 覆盖 | 所有 API 接口都有用例覆盖 |
| 测试类型覆盖 | 正常流程、异常流程、边界条件测试用例完整 |
| 级别分布合理 | L0-L2 级别分布符合参考（L0:≤30%, L1:≤40%, L2:剩余比例） |

### 2.2 可执行性检查清单

| 检查项 | 说明 |
|--------|------|
| 步骤清晰性 | 每个测试步骤都是用户可在 UI 上执行的操作 |
| 操作可行性 | 无"调用 XXX 方法"等代码级描述 |
| 输入操作明确 | 输入操作指定了具体的输入框和输入内容 |
| 点击操作明确 | 点击操作指定了具体的按钮 |
| 前置条件明确 | 前置条件是测试执行前可检查的状态 |
| 后置条件明确 | 后置条件是测试执行后可恢复的状态 |

### 2.3 可判定性检查清单

| 检查项 | 说明 |
|--------|------|
| 预期结果明确 | 预期结果具体明确，可判定 pass/fail |
| 验证点具体 | 无"功能执行正确，结果符合预期"等模糊描述 |
| 无歧义 | 无"可能"、"大概"、"应该"等不确定词汇 |
| 验证点对应 | 验证点与测试步骤一一对应 |
| 用例描述无歧义 | 用例描述唯一，无二义性 |

### 2.4 规范性检查清单

| 检查项 | 说明 |
|--------|------|
| 测试标题规范 | 使用黑盒功能视角描述（不含"调用"、"访问"、"返回"等 API 词汇） |
| 测试步骤规范 | 使用纯黑盒描述（点击、输入等 UI 操作），API 在括号内备注 |
| 预期结果规范 | 使用功能视角描述（不含"返回"、"回调"等 API 词汇） |
| API 备注规范 | 格式统一：`(API: methodName, 参数：key=value)` |
| 用例 ID 规范 | 符合命名规范（F01-001 格式） |
| Markdown 格式 | 表格格式正确，章节结构清晰 |
| JSON 格式 | JSON 格式有效，可解析 |
| 内容一致性 | JSON 与 Markdown 内容一致 |
| 模板遵循 | 严格遵循测试用例模板格式 |

## 三、评分标准

### 3.1 覆盖率评分（100 分）

| 评审项 | 分值 | 扣分规则 |
|--------|------|----------|
| 功能模块覆盖 | 25 分 | 每遗漏 1 个模块扣 10 分 |
| 测试点覆盖 | 25 分 | 每遗漏 1 个测试点扣 5 分 |
| API 覆盖 | 25 分 | 每遗漏 1 个 API 扣 5 分 |
| 测试类型覆盖 | 15 分 | 每缺少一类测试扣 5 分 |
| 级别分布合理 | 10 分 | 分布严重偏离扣 5 分 |

### 3.2 可执行性评分（100 分）

| 评审项 | 分值 | 扣分规则 |
|--------|------|----------|
| 步骤清晰性 | 30 分 | 每处不清晰扣 5 分 |
| 操作可行性 | 30 分 | 每处非 UI 操作扣 10 分 |
| 前置条件明确 | 20 分 | 每处模糊扣 5 分 |
| 后置条件明确 | 20 分 | 每处模糊扣 5 分 |

### 3.3 可判定性评分（100 分）

| 评审项 | 分值 | 扣分规则 |
|--------|------|----------|
| 预期结果明确 | 40 分 | 每处模糊扣 5 分 |
| 验证点具体 | 35 分 | 每处模糊扣 5 分 |
| 无歧义 | 25 分 | 每处歧义扣 10 分 |

### 3.4 规范性评分（100 分）

| 评审项 | 分值 | 扣分规则 |
|--------|------|----------|
| 测试标题规范 | 20 分 | 每处 API 视角描述扣 5 分 |
| 测试步骤规范 | 25 分 | 每处直接 API 调用扣 10 分 |
| 预期结果规范 | 20 分 | 每处 API 视角描述扣 5 分 |
| API 备注规范 | 15 分 | 每处格式不规范扣 5 分 |
| 用例 ID 规范 | 10 分 | 每处编号不规范扣 5 分 |
| 模板遵循 | 10 分 | 章节结构/表格格式不符每处扣 5 分 |

---

## 四、通过标准

| 维度 | 通过分数线 |
|------|------------|
| 覆盖率 | ≥ 85 分 |
| 可执行性 | ≥ 80 分 |
| 可判定性 | ≥ 80 分 |
| 规范性 | ≥ 75 分 |
| **总体** | **≥ 80 分** 且各维度均达标 |

---

## 五、评审结论

| 评审结论 | 条件 |
|---------|------|
| **通过** | 总体≥80 分 且 各维度均达标 且 三方比对 100% 一致 |
| **有条件通过** | 总体≥80 分 但有个别维度未达标，需完成必须修订项 |
| **不通过** | 总体<80 分 或 三方比对不一致 或 关键维度缺失 |
