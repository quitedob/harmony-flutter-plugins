# 测试点生成与验证点编写指南

## 概述

本文档说明如何基于 IBO 分析生成测试点，以及如何编写符合规范的测试点和验证点。

---

## 测试点数量控制

### 核心原则

**正常流程测试点不限制数量**（如枚举类型需全覆盖），**异常流程和边界值测试点按需生成，若涉及则每个模块只生成 1-2 个**。

### 数量限制规则

| 测试类型 | 数量限制 | 说明 |
|---------|---------|------|
| **正常流程** | 不限制 | 覆盖所有功能场景，枚举类型需全覆盖 |
| **异常流程** | 0-2 个/模块 | 仅当模块确实涉及异常场景时生成 |
| **边界值** | 0-2 个/模块 | 仅当模块确实涉及边界条件时生成 |

### 按需生成判断

**需要生成异常/边界测试点的情况**：
- 模块 API 有明确的参数输入验证（如路径、数值、字符串）
- 模块涉及资源管理（如存储空间、内存、网络连接）
- 模块有明确的状态转换和错误处理逻辑

**不需要生成异常/边界测试点的情况**：
- 模块仅做简单数据查询/封装，无异常可测
- 模块的异常处理已在其他模块覆盖
- 模块功能单一，无明显边界条件

### 示例

**F-01 存储卷路径获取（P0）** - 仅正常流程：
```
✅ 正确：4 个正常流程测试点
❌ 错误：添加权限相关的异常测试点（权限由系统处理）
```

**F-02 存储空间统计（P0）** - 有异常和边界：
```
✅ 正确：
  - 正常流程：6 个（不限制）
  - 异常流程：1 个（传入无效路径）
  - 边界值：1 个（存储满载场景）
  
❌ 错误：生成多个重复的异常测试点
  - 无效路径、null 路径、空字符串路径 → 保留 1 个即可
```

**枚举类型场景**：
```
✅ 正确：Toast 时长枚举有 4 个值，生成 4 个正常流程测试点（全覆盖）
  - 能显示 SHORT 时长 Toast
  - 能显示 LONG 时长 Toast
  - 能显示 INDIFINITE 时长 Toast
  - 能显示 CUSTOM 时长 Toast
```

## 测试点生成规则

### 从 Input 生成测试点

| 输入特征 | 生成规则 | 示例 |
|----------|----------|------|
| String 输入 | 有效值、空值、超长值 | 能正常显示有效消息、能正确处理空消息 |
| 数值输入 | 边界值（0、最小、最大） | 能正确处理 0 值、能处理最大值 |
| 枚举输入 | 遍历所有枚举值 | 能显示 SHORT 时长、能显示 LONG 时长 |
| 可空输入 | 传值、传 null | 能处理传值场景、能处理 null 场景 |
| 布尔输入 | true、false | 能开启功能、能关闭功能 |

### 从 Behavior 生成测试点

| 行为特征 | 生成规则 | 示例 |
|----------|----------|------|
| 状态转换 | 覆盖所有状态迁移 | 能从状态 A 切换到状态 B |
| 数据计算 | 验证计算结果 | 计算结果准确 |
| 异步行为 | 验证异步执行 | 异步操作正确完成 |
| 队列管理 | 验证 FIFO 顺序 | 多个请求按序处理 |
| UI 渲染 | 验证显示效果 | UI 显示符合预期 |

### 从 Output 生成测试点

| 输出特征 | 生成规则 | 示例 |
|----------|----------|------|
| 列表输出 | 空列表、有元素 | 无数据时返回空列表、有数据时返回完整列表 |
| 数值输出 | 精度验证 | 返回值精度正确 |
| 对象输出 | 属性完整性 | 返回对象包含所有必要属性 |
| 可空输出 | null 处理 | 无数据时返回 null |

## 测试点级别划分

### 级别判定规则

| 模块优先级 | 测试类型 | 级别 |
|-----------|---------|------|
| P0 | 正常流程 | L0 |
| P0 | 异常/边界 | L1 |
| P1 | 正常流程（1-2 个最基础） | L0 |
| P1 | 正常流程（其他） | L1 |
| P1 | 异常/边界 | L2 |
| P2 | 正常流程（1-2 个最基础） | L0 |
| P2 | 正常流程（其他） | L1 |

**注意**：L3 级别已废弃，P2 模块不再生成异常/边界测试点。

### 级别分布参考

| 级别 | 占比控制 | 说明 |
|------|----------|------|
| L0 | ≤30% | 核心功能正常流程 + P1/P2 基础正常流程 |
| L1 | ≤40% | P0 其他正常流程 + P1/P2 其他正常流程 |
| L2 | 剩余比例 | P0 异常/边界 + P1 异常/边界 |

**注意**：L3 级别已废弃，不再使用。

## 验证点编写要求

### 核心要求

- **必须具体明确**：体现测试点的具体验证内容
- **禁止模糊描述**：不能使用"功能执行正确，结果符合预期"等通用描述
- **必须有判定标准**：测试人员可以根据验证点明确判定 pass/fail

### 示例对比

| 测试点 | 验证点（正确）✅ | 验证点（错误）❌ |
|--------|--------------|--------------|
| 能正常显示短时长 Toast | Toast 显示时长为短时长（约 2 秒） | 功能执行正确，结果符合预期 |
| 能显示将来电号码 | 显示正确的 11 位手机号码 | 返回数据准确 |
| 能统计通话时长 | 显示通话持续时间（秒），随时间递增 | 统计结果正确 |
| 能处理空消息输入 | Toast 不显示或使用默认消息 | 功能正常处理 |

## 测试点描述规范

### API 层面 → 功能层面转化

| API 层面描述（避免）❌ | 功能层面描述（推荐）✅ |
|---------------------|---------------------|
| `调用 showToast() 方法成功` | `能正常显示 Toast` |
| `访问 status 属性返回 CALL_INCOMING` | `能显示状态为"来电中"` |
| `调用 stream 订阅事件流` | `能接收事件流更新` |
| `调用 enable() 方法成功` | `能开启功能` |
| `调用 disable() 方法成功` | `能关闭功能` |

### 转化规则总结

| API 层面词汇 | 功能层面转化 |
|------------|-------------|
| `调用 XXX()` | `能执行 XXX` / `能正常 XXX` |
| `访问 XXX 属性` | `能获取/显示 XXX` |
| `返回 XXX 值` | `能正确显示 XXX` |
| `订阅 XXX 事件` | `能接收 XXX 事件` |

## 测试点格式规范

| 字段 | 要求 | 示例 |
|------|------|------|
| 测试点编号 | 模块 ID+ 序号 | F-01-01 |
| 功能模块 | 模块名称 | 原生 Toast 显示 |
| 测试点 | 具体测试内容描述（功能视角） | 能正常显示默认 Toast，约 2 秒后自动消失 |
| 验证点 | 具体的验证标准 | Toast 显示默认消息，约 2 秒后自动消失 |
| 覆盖 API | 被测 API 名称 | showToast |
| 测试点级别 | L0/L1/L2 | L0 |
