# hmos-library-quality-assessment

> 鸿蒙 ArkTS 三方库白盒质量评估 Skill —— 从**架构 / 代码质量**两大维度审查 HAR/HSP 库，产出按 🔴/🟡/🟢（+💡 非阻塞注解）分级的发现清单与定性结论。

## 它做什么

对一个 ArkTS 三方库（HAR/HSP）做白盒评估，**仅三类检查项**：

- **CodeLinter 静态扫描**（硬前置）：启用全部规则集扫描，按级别 + 规则集汇总为独立报告节。
- **通用架构（A1）** — SOLID、耦合内聚、反模式、分层依赖方向（语言无关）。
- **代码质量（B1）** — ArkTS 规范 / 复杂度 / 错误处理 / 逻辑性能 / 加密安全。

> 不含 UI 专项维度（组件契约 / 渲染性能 / 无障碍等）。阶段0 库画像不判定 UI/逻辑/NAPI 库型，也不展开独立 UI 维度。

**只评估、只读** —— 绝不修改被评估库，不调用 `--fix`。报告**仅分级发现 + 定性结论**（✅推荐/⚠️谨慎使用/❌不推荐），不打分、不评等级。

## 工作流程（5 阶段）

| 阶段 | 内容 |
|------|------|
| 0 库画像 | 用 Read + `find`/`wc` 识别库名/版本、产物类型、导出/依赖、规模 |
| 1 静态扫描 | **CodeLinter（硬前置）**：全量规则集扫描，按级别 + 规则集汇总为独立报告节；无 DevEco 则中止、不产报告 |
| 2 架构评审 | A1 通用架构，人工白盒判断 |
| 3 代码质量评审 | B1 通用·逻辑，人工白盒判断 |
| 4 报告 | 套用 `assets/assessment-report-template.md` 产出 |

> 唯一外部依赖是 CodeLinter **二进制**（随 DevEco Studio 分发）——硬性前置，缺失则中止评估、不产报告。
