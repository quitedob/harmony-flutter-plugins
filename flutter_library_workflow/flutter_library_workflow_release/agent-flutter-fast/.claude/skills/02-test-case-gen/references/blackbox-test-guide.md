# 黑盒测试用例编写指南

## 概述

本指南指导如何将测试点转化为黑盒测试用例，确保测试步骤从用户视角描述，可执行、可判定。

**适用范围**：阶段 4 - 测试用例生成

---

## 一、黑盒测试原则

### 1.1 纯黑盒视角

| 要求 | 说明 |
|------|------|
| ✅ 必须 | 测试步骤描述用户界面操作或功能行为 |
| ✅ 必须 | API 信息在步骤后的括号内备注 |
| ❌ 禁止 | 直接写 API 调用代码 |
| ❌ 禁止 | 使用"调用"、"访问"、"返回"等 API 层面词汇 |

### 1.2 示例对比

| 白盒/API 层面（错误） | 黑盒/功能层面（正确） |
|---------------------|---------------------|
| `调用 showToast(msg: "测试")` | `点击【显示 Toast】按钮 (API: showToast, msg: "测试")` |
| `访问 status 属性` | `观察当前电话状态显示 (API: status)` |
| `订阅 stream 事件流` | `开启电话状态监听功能 (API: stream)` |
| `调用 enableWakeLock()` | `启用屏幕常亮功能 (API: enableWakeLock)` |
| `检查返回值是否为 true` | `验证屏幕保持常亮状态` |

## 二、测试用例结构

### 2.1 基本结构

| 字段 | 说明 | 示例 |
|------|------|------|
| 用例 ID | 直接使用测试点 ID | F-01-01 |
| 测试标题 | 测试内容概要 | 能正常显示默认 Toast |
| 测试级别 | L0/L1/L2 | L0 |
| 前置条件 | 执行测试前的状态 | 应用已启动；功能界面已打开 |
| 测试步骤 | 用户可执行的操作步骤 | 1. 在输入框中输入... 2. 点击【...】按钮 |
| 预期结果 | 明确的判定标准 | Toast 显示默认消息，约 2 秒后自动消失 |
| 后置条件 | 测试执行后的状态 | 选填，字段保留但内容留空 |

### 2.2 JSON 结构

```json
{
  "id": "F-01-01",
  "title": "测试标题",
  "level": "L0",
  "preconditions": "前置条件",
  "test_steps": [
    {
      "action": "点击【显示】按钮",
      "checkpoint": "验证点"
    }
  ],
  "expected_result": "预期结果",
  "postconditions": ""
}
```

## 三、插件类型与测试编写策略

### 3.1 UI 组件类插件

**特征**：有可见界面、按钮、输入框、开关等 UI 元素

**步骤描述方式**：
- 点击【XXX】按钮
- 在【XXX 输入框】中输入文本
- 在【XXX 下拉框】中选择选项
- 将【XXX 开关】切换为开启/关闭状态

**示例**：
```
1. 在【消息输入框】中输入文本"测试消息"
2. 点击【显示 Toast】按钮 (API: showToast, msg: "测试消息", length: SHORT)
3. 观察 Toast 显示和消失
```

**预期结果示例**：
- Toast 显示默认消息，约 2 秒后自动消失
- 按钮颜色从蓝色变为灰色
- 列表新增一条记录

---

### 3.2 后台服务类插件

**特征**：事件监听、状态监控、后台任务、无明显 UI 界面

**步骤描述方式**：
- 启动应用并进入 XX 功能界面
- 观察 XX 状态显示
- 模拟 XX 事件触发
- 验证应用反应/状态变化

**示例（phone_state）**：
```
1. 启动应用并进入电话状态监听界面 (API: PhoneState.nothing)
2. 观察电话状态显示
3. 模拟来电事件触发
4. 观察状态变化显示 (API: stream)
```

**预期结果示例**：
- 电话状态显示为"待机"或"无通话"
- 状态从"待机"切换为"来电中"
- 状态栏显示通知图标

---

### 3.3 平台交互类插件

**特征**：调用系统 API（蓝牙、相机、传感器、定位等）

**步骤描述方式**：
- 启动应用，授权 XX 权限
- 点击【开启 XX】按钮
- 观察系统反应
- 验证功能执行结果

**示例（蓝牙插件）**：
```
1. 启动应用，在权限对话框中点击"允许"
2. 点击【开启蓝牙】按钮 (API: enableBluetooth)
3. 观察蓝牙开启状态
4. 验证蓝牙功能可用
```

**预期结果示例**：
- 蓝牙状态显示为"已开启"
- 附近设备列表刷新
- 蓝牙图标显示在状态栏

---

### 3.4 工具类插件

**特征**：纯功能计算、数据处理、无 UI 交互

**步骤描述方式**：
- 输入 XX 数据
- 执行 XX 操作
- 验证输出结果

**示例（JSON 解析插件）**：
```
1. 在【JSON 输入框】中输入 JSON 数据
2. 点击【解析】按钮 (API: parseJson)
3. 观察解析结果
4. 验证结果格式正确
```

**预期结果示例**：
- 解析结果以树形结构显示
- 错误输入显示错误提示
- 支持复制解析结果

## 四、测试步骤编写规范

### 4.1 基本格式

```
1. 在【XXX 输入框】中输入文本"XXX"
2. 点击【XXX】按钮 (API: methodName, 参数：key=value)
3. 等待 X 秒
4. 验证【XXX】显示正确
5. 记录结果
```

### 4.2 API 备注格式

在步骤描述后的括号内备注 API 信息：

```
格式：(API: ClassName.methodName, 参数名：值)

示例：
- (API: showToast, msg: "测试消息", toastLength: LENGTH_SHORT)
- (API: FToast.init, context: BuildContext)
- (API: cancel)
```

### 4.3 常见操作描述

| 操作类型 | 标准描述 |
|----------|----------|
| 输入文本 | `在【XXX 输入框】中输入文本"XXX"` |
| 选择选项 | `在【XXX 下拉框】中选择"XXX"选项` |
| 点击按钮 | `点击【XXX】按钮` |
| 切换开关 | `将【XXX 开关】切换为开启/关闭状态` |
| 等待 | `等待 X 秒` |
| 验证显示 | `验证【XXX】显示正确/存在` |
| 记录结果 | `记录 XXX 结果` |

### 4.4 后台服务类操作描述

| 操作类型 | 标准描述 | 示例 |
|----------|----------|------|
| 启动/初始化 | `启动应用并进入 XX 功能界面` | `启动应用并进入电话状态监听界面` |
| 观察状态 | `观察【XXX】状态显示` | `观察电话状态显示` |
| 模拟事件 | `模拟 XX 事件触发` | `模拟来电事件触发` |
| 验证反应 | `验证应用反应/状态变化` | `验证状态切换为"来电中"` |
| 授权权限 | `在系统权限对话框中点击"允许"` | `在电话状态权限对话框中点击"允许"` |

## 五、预期结果编写

### 5.1 要求

- 具体明确，可直观判定
- 避免"可能"、"应该"、"大概"等模糊词汇
- 包含具体的验证标准

### 5.2 示例对比

| 测试点 | 预期结果（正确） | 预期结果（错误） |
|--------|----------------|----------------|
| 能正常显示短时长 Toast | Toast 显示默认消息，约 2 秒后自动消失 | Toast 正常显示 |
| 能显示来电号码 | 显示正确的 11 位手机号码 | 返回数据正确 |
| 能统计通话时长 | 显示通话持续时间（秒），随时间递增 | 统计功能正常 |
| 能检测新版本 | 显示更新弹窗，包含版本号和更新内容 | 检测功能正常 |

## 六、测试用例级别判定

### 6.1 级别定义

| 级别 | 说明 | 判定规则 |
|------|------|----------|
| L0 | 核心功能（P0）的正常流程，以及 P1、P2 功能模块的 1-2 个最基础正常流程 | P0 模块 + 正常流程；P1/P2 模块 + 1-2 个最基础正常流程 |
| L1 | 核心功能（P0）的异常/边界流程，或重要功能（P1）的其他正常流程 | P0 模块 + 异常/边界，或 P1 模块 + 其他正常流程 |
| L2 | 重要功能（P1）的异常/边界流程，或辅助功能（P2）的其他正常流程 | P1 模块 + 异常/边界，或 P2 模块 + 其他正常流程 |

**注意**：L3 级别已废弃，P2 模块的异常/边界流程不再生成测试用例。

### 6.2 级别分布参考

| 级别 | 占比参考 | 说明 |
|------|----------|------|
| L0 | ≤30% | 核心功能的正常流程 + P1/P2 最基础正常流程 |
| L1 | ≤40% | P0 其他正常流程 + P1/P2 其他正常流程 |
| L2 | 剩余比例 | P0 异常/边界 + P1 异常/边界 |

**注意**：L3 级别已废弃，不再使用。

## 七、质量检查清单

在输出测试用例前，检查以下项目：

| 检查项 | 通过标准 | 不通过处理 |
|--------|---------|-----------|
| 测试标题 | 不含 API 方法名，使用功能视角描述 | 修改为功能描述 |
| 测试步骤 | 描述用户操作/行为观察 | 修改为"点击..."、"观察..." |
| API 备注 | 在步骤后括号内备注，格式正确 | 确保格式为 `(API: xxx)` |
| 预期结果 | 具体可判定，无模糊词汇 | 不含"可能"、"应该"等 |
| 前置条件 | 明确具体，可检查 | 补充缺失条件 |
| 后置条件 | 描述测试后状态，字段保留但内容留空 | 补充为空字符串 |
| 级别判定 | 符合 L0-L2 判定规则 | 调整级别 |
| 三方一致性 | 模块数、用例总数、级别分布一致 | 修正数据 |

## 八、完整用例示例

### 8.1 UI 组件类示例（fluttertoast）

```
用例 ID: F-01-01
测试标题：能正常显示默认 Toast，约 2 秒后自动消失
测试级别：L0
前置条件：应用已启动；功能界面已打开
测试步骤：
1. 点击【显示 Toast】按钮 (API: showToast, msg: "默认消息")
2. 观察 Toast 显示和消失
预期结果：Toast 显示默认消息，约 2 秒后自动消失
后置条件：""
```

### 8.2 后台服务类示例（phone_state）

```
用例 ID: F-01-01
测试标题：能显示初始待机状态
测试级别：L0
前置条件：应用已启动

1. 启动应用并进入电话状态监听界面 (API: PhoneState.nothing)
2. 观察电话状态显示
预期结果：电话状态显示为"待机"或"无通话"
后置条件：""

用例 ID: F-01-08
测试标题：来电时状态变化通知正确
测试级别：L0
前置条件：应用已启动；已点击【开始监听】按钮
测试步骤：
1. 模拟来电事件触发

3. 验证状态切换为"来电中"

后置条件：""
```

### 8.3 平台交互类示例（update 插件）

```
用例 ID: F-02-01
测试标题：能正确检测并显示无新版本状态
测试级别：L0
前置条件：应用已启动；版本检测 URL 已配置
测试步骤：
1. 进入【版本更新】功能界面
2. 点击【检查更新】按钮 (API: checkUpdate)
3. 等待 3 秒
4. 观察界面提示
预期结果：界面显示"已是最新版本"提示，无更新弹窗
后置条件：""

用例 ID: F-02-03
测试标题：能正确检测并显示强制更新弹窗
测试级别：L1
前置条件：应用已启动；服务器配置为强制更新
测试步骤：
1. 进入【版本更新】功能界面
2. 点击【检查更新】按钮 (API: checkUpdate)
3. 等待更新弹窗显示
4. 尝试点击弹窗的【取消】按钮（如有）或物理返回键
预期结果：显示更新弹窗，弹窗不可取消（无【取消】按钮，物理返回键无效）
后置条件：""
```
