# media_scanner 鸿蒙适配方案

## 方案概述

`media_scanner` 是一个 standalone MethodChannel Flutter 插件，原本仅支持 Android。鸿蒙适配采用 **单包直接注册** 架构：在 Dart 层做平台分支（`TargetPlatform.ohos` 走 `loadMedia`、Android 走 `refreshGallery`），在 OHOS 原生层用 `@kit.MediaLibraryKit` 的 `MediaAssetChangeRequest` + `PhotoAccessHelper.applyChanges()` 替代 Android 的 `MediaScannerConnection.scanFile()`。适配已完成并构建通过，代码位于 `repos-flutter-fast/media_scanner`。

### 核心实现思路

1. **平台路由**（Dart 层，0 行新增）：`lib/media_scanner.dart` 第 43-49 行，`defaultTargetPlatform == TargetPlatform.ohos` 时通过 MethodChannel `"media_scanner"` 调用 `loadMedia` 方法，Android 走原有 `refreshGallery`。
2. **媒体注册**（ArkTS 层）：`ohos/src/main/ets/.../MediaScannerPlugin.ets` 接收 `loadMedia` 调用，按文件扩展名判定 `PhotoType`（IMAGE/VIDEO），构造 `MediaAssetChangeRequest.createImageAssetRequest / createVideoAssetRequest`，然后 `await helper.applyChanges(changeRequest)` 完成系统媒体库注册。
3. **权限策略**：使用受限权限 `ohos.permission.WRITE_IMAGEVIDEO`，采用**双层防御**——EntryAbility 启动时申请（第一层），插件 `ensureWriteMediaPermission()` 在每次 `registerAsset` 前再检查→必要时弹窗请求（第二层）。若用户拒绝返回 code=201 错误。
4. **输入契约**：OHOS 侧必须传应用沙箱 `file://` URI，不接受 Android 式 `/storage/emulated/0/...` 路径。返回成功为 `null`，失败为错误描述字符串。

## 架构决策

### 单包 vs Federated

- **决策**：单包 standalone，不拆分子包
- **原因**：插件 API 极简（仅 1 个公开方法），拆分 federated 增加维护成本无实际收益。pubspec.yaml 中 `ohos` 和 `android` 平级注册在同一 `flutter.plugin.platforms` 下。

### Method Channel 方法名分叉

- **决策**：Android 保留 `refreshGallery`，HarmonyOS 新增 `loadMedia`
- **原因**：OHOS API 参数语义从"文件系统路径"变为"应用沙箱 file URI"，分开方法名使两端原生 handler 各自明确契约，避免混淆。

### 权限模式

- **决策**：动态 `requestPermissionsFromUser` + AbilityAware 能力预留
- **原因**：WRITE_IMAGEVIDEO 为受限权限，无法仅靠 module.json5 静态声明生效。双层检查确保 EntryAbility 拒绝后插件仍有补救机会。

## 风险项

| 风险 | 严重度 | 缓解方案 |
|------|--------|----------|
| MediaAssetChangeRequest 仅接受 file URI；传入普通路径返回 401 / 13900002 | high | Dart 文档明确要求 sandbox URI；调用前做格式校验 |
| WRITE_IMAGEVIDEO 受限权限被用户拒绝返回 201 | high | 双层防御 + 返回明确错误字符串给 Dart 侧 |
| 当前 standalone 仓库未重新执行完整 18 条自动化测试 | medium | 重新运行 MethodChannel/Dart 测试 + HAP 构建 + 真机图库验收 |
| 旧 donor（media_scanner_ohos）的 18/18 结果不能继承 | medium | 以当前仓库重新验证为验收标准 |
| 未知扩展名（.xyz）系统返回 401 | low | 属于预期系统校验，已在历史 donor 测试中确认 |
