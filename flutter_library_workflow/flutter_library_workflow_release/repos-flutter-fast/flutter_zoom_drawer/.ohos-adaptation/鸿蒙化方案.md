# flutter_zoom_drawer 鸿蒙适配方案

## 方案概述

`flutter_zoom_drawer` 是一个 pure-Dart UI 组件，零原生代码、零 MethodChannel、零权限需求。鸿蒙适配仅需 **1 行 Dart 代码**：在 `lib/src/flutter_zoom_drawer.dart` 第 824-828 行的 `PopScope` 平台条件中增加 `TargetPlatform.ohos` 匹配，使 OHOS 设备上系统返回手势/键能正确关闭抽屉。无需创建 `ohos/` HAR 工程，无需声明任何权限。适配已完成并构建通过，代码位于 `repos-flutter-fast/flutter_zoom_drawer`。

### 核心实现思路

1. **返回行为适配**（唯一改动）：原始代码仅对 `TargetPlatform.android` 包裹 `PopScope`，导致 OHOS 上返回键不拦截（抽屉打开时直接退出页面而非先关抽屉）。增加 `|| TargetPlatform.ohos` 后，OHOS 设备返回行为与 Android 一致。
2. **零原生层**：所有动画（`AnimationController`）、手势（`GestureDetector`）、变换（`Matrix4` rotateZ/translate/scale）、返回拦截（`PopScope`）均为 Flutter Framework 标准 API，Flutter OHOS Engine 完整支持。
3. **验证重点**：四种内置动画风格（Style1-4）在 OHOS GPU 渲染路径上的视觉正确性、RTL 布局、拖拽灵敏度、2in1 设备无物理返回键的替代关闭方式。

无。该插件不调用任何平台原生 API，所有功能均在 Flutter Framework 层完成。

## 架构决策

### 不做 Fork 直接引入

- **决策**：不创建独立 OHOS Fork 仓库，在原仓库做最小改动
- **原因**：改动仅 1 行，建议向上游提 PR（`medyas/flutter_zoom_drawer`）。用户可直接依赖 pub.dev 原包，在 OHOS 设备上只需确保 `TargetPlatform.ohos` 被正确识别。

### 无 OHOS 原生工程

- **决策**：`pubspec.yaml` 不声明 `ohos` 平台，不创建 `ohos/` 目录
- **原因**：pure-Dart 包无需平台注册，Flutter 插件系统不会为其查找原生代码。

### Example 独立 OHOS 工程

- **决策**：Example 的 `ohos/` 目录仅用于在真机上验证组件行为
- **原因**：Example 是独立 Flutter 应用，需要 `ohos/` 工程才能 `flutter build hap`。Example 依赖的 `shared_preferences`、`provider` 等包在 OHOS 侧的状态按各自适配进度处理，不阻塞本组件的纯 UI 验证。

## 风险项

| 风险 | 严重度 | 缓解方案 |
|------|--------|----------|
| Matrix4 rotateZ 3D 旋转（Style 3/4）在 OHOS GPU 驱动上可能有细微渲染差异 | low | 真机验证 Style 3/4 动画；用户可通过 `angle` 参数调整 |
| OHOS 触摸驱动手势灵敏度差异 | low | `dragOffset`/`openDragSensitivity`/`closeDragSensitivity` 参数可调 |
| 2in1 设备无物理返回键，PopScope 仅拦截系统手势 | medium | mainScreenTapClose + 关闭按钮 + 滑动手势 3 种替代关闭方式 |
| Example 中 `shared_preferences` 需 OHOS 适配版 | low | Example 验证时可暂时移除或 mock 该依赖的持久化功能 |
| 当前 ZIP 中 `test/flutter_zoom_drawer_test.dart` 为空壳 | medium | 需将完整 29 条测试和测试页同步到打包源后重新执行 |
