# test-case-gen - 测试用例生成 Skill

## 概述

基于测试分析报告生成纯黑盒测试用例，输出 Markdown 和 JSON 格式。

**适用范围**：阶段 4 - 测试用例生成  
**输入**：测试分析报告、测试点汇总 JSON、评审结果 JSON  
**输出**：测试用例 Markdown、测试用例 JSON

---

## 输入参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `plugin_name` | 是 | 插件/库名称 |
| `test_analysis_path` | 是 | 测试分析报告路径 |
| `output_dir` | 否 | 输出目录（默认为 `.ohos-adaptation`） |

---

## 输出文件

| 文件 | 说明 |
|------|------|
| `{output_dir}/04-test-cases.md` | 测试用例（Markdown） |
| `{output_dir}/04-test-cases.json` | 测试用例（JSON，符合 test_suite schema） |

## 核心原则

### 纯黑盒视角

| 要求 | 说明 |
|------|------|
| ✅ 必须 | 测试步骤描述用户界面操作（点击、输入、等待、观察等） |
| ✅ 必须 | API 信息在步骤后的括号内备注 |
| ❌ 禁止 | 直接写 API 调用代码 |
| ❌ 禁止 | 使用"调用"、"访问"、"返回"等 API 层面词汇 |

**示例**：
- ✅ `点击【显示 Toast】按钮 (API: showToast, msg: "测试消息")`
- ❌ `调用 showToast(msg: "测试消息")`

## UI 可操作性原则（用于 Demo 应用生成）

**重要**：生成的测试用例将用于自动生成 Demo 应用并进行 UI 自动化测试。

### 核心要求

| 要求 | 说明 | 示例 |
|------|------|------|
| **明确的 UI 元素** | 必须使用【】标注 UI 元素名称 | `点击【分享】按钮 `、`在【消息】输入框中输入` |
| **标准操作动词** | 必须使用可执行的操作动词 | 点击、输入、选择、滑动、等待、观察 |
| **可观察的验证点** | checkpoint 必须描述可观察的 UI 状态变化 | `验证【分享成功】提示显示 `、`验证按钮变为"已发送"状态` |

### 标准操作动词

| 操作类型 | 动词 | 示例 |
|----------|------|------|
| **点击操作** | 点击、按压 | `点击【确定】按钮`、`按压【Home】键` |
| **输入操作** | 输入、清除、填写 | `在【消息】输入框中输入"测试内容"` |
| **选择操作** | 选择、取消选择、勾选 | `选择【同意】复选框`、`选择【第一个】选项` |
| **滑动操作** | 滑动、滚动、拖动 | `向上滑动屏幕`、`拖动滑块到最右端` |
| **导航操作** | 打开、进入、返回、跳转 | `打开【设置】页面`、`返回上一级` |
| **等待操作** | 等待、暂停 | `等待 3 秒`、`等待【加载完成】提示出现` |
| **观察操作** | 观察、验证、确认 | `观察【分享对话框】是否打开` |

### UI 元素命名规范

| UI 元素类型 | 命名格式 | 示例 |
|------------|---------|------|
| 按钮 | 【XX】按钮 | `【分享】按钮 `、`【确定】按钮` |

| 列表/选项 | 【XX】列表/选项 | `【分享目标】列表 `、`【第一个】选项` |
| 页面/界面 | 【XX】页面/界面 | `【设置】页面 `、`【分享】界面` |
| 对话框 | 【XX】对话框 | `【确认】对话框 `、`【分享成功】提示框` |
| 复选框 | 【XX】复选框 | `【同意】复选框 `、`【记住密码】复选框` |
| 开关 | 【XX】开关 | `【启用】开关 `、`【夜间模式】开关` |
| 下拉菜单 | 【XX】下拉菜单 | `【分享方式】下拉菜单` |

> **详细指南**：UI 元素命名规范详解、自动化脚本转换示例、错误写法对比见 `references/blackbox-test-guide.md`

## 执行流程

| 步骤 | 名称 | 说明 |
|------|------|------|
| 1 | 读取测试分析结果 | 读取评审后的测试分析报告和测试点 JSON |
| 2 | 逐模块转化用例 | 将每个测试点转化为黑盒测试用例 |
| 3 | 生成 JSON 文档 | 生成符合 schema 的 JSON 测试用例 |
| 4 | 生成 Markdown 文档 | 生成表格格式的测试用例文档 |
| 5 | 三方一致性校验 | 校验模块数、用例总数、级别分布 |
| 6 | 最终质量自检 | 检查 Markdown 与 JSON 一致性、格式是否符合模板 |
| 7 | 输出生成统计 | 输出用例总数、级别分布等 |

## 模板格式严格执行要求

**重要：生成测试用例时必须严格遵守以下要求，不得修改模板格式**

### 1. JSON 格式严格要求

- **必须** 包含 `suite` 字段（id、name、app_package、app_card）
- **必须** 包含 `modules` 数组，每个模块包含 moduleCode、moduleName、moduleDescription、priority、test_cases
- **必须** 每个测试用例包含：id、title、level、preconditions、test_steps、expected_result、postconditions
- **必须** `test_steps` 数组中每个步骤只包含 `action` 和 `checkpoint` 两个字段
- **禁止** 添加 `step`（步骤编号）字段
- **禁止** 添加 `coveredAPI` 字段（API 信息只在 Markdown 中备注）
- **禁止** 添加任何其他模板中没有的字段

### 2. Markdown 格式严格要求

- **必须** 使用表格清单格式，表头为：`| 用例 ID | 测试标题 | 测试级别 | 前置条件 | 测试步骤 | 预期结果 | 后置条件 |`
- **必须** 每个模块使用 `### F-XX {模块名称}（{优先级}）` 三级标题
- **必须** 测试步骤使用 `<br>` 分隔多个步骤
- **必须** API 信息在步骤后括号内备注，格式：`(API: apiName)`
- **禁止** 使用 `| 项目 | 内容 |` 表格格式
- **禁止** 每个用例独立成表（应使用一行表格呈现一个用例）

### 3. 格式验证步骤

生成完成后必须执行以下验证：
- [ ] JSON 文件可以被 json.load() 正确解析
- [ ] JSON 中 test_steps 的每个步骤只包含 action 和 checkpoint 两个字段
- [ ] JSON 中没有 step、coveredAPI 等额外字段
- [ ] Markdown 表格表头正确
- [ ] Markdown 中每个用例占一行（不是一例一表）
- [ ] Markdown 与 JSON 的模块数、用例总数、级别分布一致

## 测试用例结构

### JSON 格式

**必须严格按照以下格式，不添加或减少任何字段**：

```json
{
  "$schema": "https://raw.githubusercontent.com/HarmonyOS-AI/json-schema/main/droidrun/test_suite.schema.json",
  "suite": {
    "id": "{plugin_name}_test_suite",
    "name": "{plugin_name} 测试套件",
    "app_package": "{app_package}",
    "app_card": "file:./{plugin_name}.md"
  },
  "modules": [
    {
      "moduleCode": "F-01",
      "moduleName": "{模块名称}",
      "moduleDescription": "{模块描述}",
      "priority": "{P0/P1/P2}",
      "test_cases": [
        {
          "id": "F01-001",
          "title": "{测试标题}",
          "level": "{L0/L1/L2/L3}",
          "preconditions": "{前置条件}",
          "test_steps": [
            {
              "action": "{操作描述}",
              "checkpoint": "{验证点}"
            }
          ],
          "expected_result": "{预期结果}",
          "postconditions": "{后置条件}"
        }
      ]
    }
  ]
}
```

**注意**：
- `test_steps` 中每个步骤包含 `action` 和 `checkpoint` 两个字段
- **不要添加** `step`、`coveredAPI` 或其他额外字段
- API 信息在 Markdown 中的步骤后括号内备注，不在 JSON 中添加字段

### Markdown 格式

**必须严格按照模板格式，使用表格清单格式**：

```markdown
# {plugin_name} 黑盒测试用例

## 测试范围概述

{plugin_description}

- **测试范围说明**：覆盖所有公开功能，从用户视角进行黑盒测试
- **测试级别说明**：
  - L0 = 核心功能的正常流程，必测项
  - L1 = 核心功能的异常/边界 + 重要功能的正常流程
  - L2 = 重要功能的异常/边界 + 辅助功能的正常流程
  - L3 = 辅助功能的异常/边界

## 功能模块划分

| 模块编号 | 功能模块 | 描述 | 优先级 |
|---------|---------|------|--------|
| F-01 | ... | ... | P0 |

|--------|----------|----------|----------|:----------|----------|----------|
| F02-001 | {测试标题} | L0 | {前置条件} | 1. {步骤 1}<br>2. {步骤 2} | {预期结果} | {后置条件} |
```

**Markdown 格式要求**：
- 文档标题：`# {plugin_name} 黑盒测试用例`
- 测试范围概述：简要描述插件功能
- 功能模块划分：表格列出所有模块
- 测试用例清单：按模块分章节，每个模块使用 `### F-XX {模块名称}（{优先级}）` 标题
- 测试用例表格：表头为 `| 用例 ID | 测试标题 | 测试级别 | 前置条件 | 测试步骤 | 预期结果 | 后置条件 |`
- 测试步骤：使用 `<br>` 分隔多个步骤，API 信息在括号内备注
- 测试覆盖率统计：表格列出各级别用例数和占比

## 质量要求

| 要求 | 说明 |
|------|------|
| 纯黑盒视角 | 不描述内部 API 调用，只描述用户操作 |
| 测试步骤可执行 | 每个步骤为用户可在 UI 上执行的操作 |
| **UI 可操作性** | **测试步骤必须能转换成 UI 自动化脚本** |
| API 信息备注 | API 信息在步骤后括号内备注 |
| 完整性 | 测试点 100% 转化为测试用例 |
| 一致性 | Markdown 与 JSON 内容完全一致 |
| **平台无关性** | **测试用例中不应体现 Android、iOS 等源平台特定内容** |
| **模板格式** | **必须严格按照模板格式生成，不得修改或自创新格式** |

### 质量检查清单

生成测试用例后必须检查以下项目：

**UI 可操作性检查**：
- [ ] 每个测试步骤都包含【】标注的 UI 元素名称
- [ ] 每个测试步骤都使用了标准操作动词（点击、输入、选择等）
- [ ] 每个 checkpoint 都描述了可观察的 UI 状态变化
- [ ] 无模糊操作描述（如"进行操作"、"执行功能"）
- [ ] 无 API 调用描述
- [ ] 测试步骤可以被转换成自动化测试脚本

**平台无关性检查**：
- [ ] 测试用例中不包含 "Android"、"iOS" 等平台特定词汇
- [ ] 测试用例中不包含源平台特有的版本号（如 "Android 12+"、"iOS 15+"）
- [ ] 测试用例中不包含源平台特有的 API 名称
- [ ] 平台版本示例应使用 "HarmonyOS NEXT" 或 "API XX"

**格式合规性检查**：
- [ ] JSON 文件可以被 json.load() 正确解析
- [ ] JSON 中 test_steps 的每个步骤只包含 action 和 checkpoint 两个字段
- [ ] JSON 中没有 step、coveredAPI 等额外字段
- [ ] Markdown 表格表头正确
- [ ] Markdown 中每个用例占一行（不是一例一表）
- [ ] Markdown 与 JSON 的模块数、用例总数、级别分布一致

> **详细指南**：测试步骤转换示例、违反要求的处罚规则见 `references/blackbox-test-guide.md`

## 边界情况处理

| 情况 | 处理方式 |
|------|---------|
| 测试点无 coveredAPI | Markdown 中备注 `(API: 未知)`，JSON 中不添加相关字段 |
| 测试点只有一个步骤 | test_steps 数组只包含一个元素 |
| 测试点有多个验证点 | 合并到一个 checkpoint 字段中，用分号分隔 |
| 前置条件为空 | 使用默认值"应用已启动" |
| 后置条件为空 | 使用默认值"可返回上一级或桌面" |
| UI 元素名称不明确 | 根据功能推断合理的元素名称，如【分享】按钮、【确定】按钮 |
