# analysis-review - 测试分析报告评审 Skill

## 概述

`analysis-review` Skill 用于评审**测试分析报告**（阶段 3 产物）的完整性和准确性。

**适用范围**：阶段 3 - 测试分析报告评审  
**评审对象**：`02-test-analysis-report.md`、`02-test-points.json`

> **注意**：测试用例评审（阶段 5）由 `case-review` Skill 独立处理。

---

## 输入参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `review_type` | 是 | 固定为 `analysis_report` |
| `input_files` | 是 | 输入文件路径数组：`[02-test-analysis-report.md, 02-test-points.json, 00-requirement.json]` |
| `output_dir` | 否 | 输出目录（默认为 `.rn-ohos-adaptation`） |

---

## 输出文件

| 文件 | 说明 |
|------|------|
| `{output_dir}/03-analysis-review-report.md` | 评审报告（Markdown，供人工审阅） |
| `{output_dir}/03-analysis-review.json` | 评审结果 JSON（供程序化处理） |
| `{output_dir}/02-test-analysis-report-revised.md` | 修订后的测试分析报告（如有修改） |

---

## 评审维度

| 维度 | 权重 | 通过线 |
|------|------|--------|
| 完整性 | 30% | ≥80 分 |
| 准确性 | 30% | ≥80 分 |
| 测试点评审（三方比对） | 25% | 100 分（必须完全一致） |
| 测试点质量 | 25% | ≥75 分 |
| 兼容性 | 15% | ≥80 分 |

**通过标准**：总体≥80 分 且 各维度均达标 且 三方比对 100% 一致

---

## 执行步骤

### 步骤 1：读取评审材料

读取以下文件：
- `.rn-ohos-adaptation/02-test-analysis-report.md` - 测试分析报告
- `.rn-ohos-adaptation/02-test-points.json` - 测试点汇总 JSON
- `.rn-ohos-adaptation/00-requirement.json` - 需求解析 JSON

### 步骤 2：执行三方比对校验

> **校验脚本**：见 `scripts/verify_analysis.py`

**校验内容**：
1. 模块数校验：测试点 JSON = Markdown 报告 = 需求解析 JSON
2. 用例总数校验：测试点 JSON = Markdown 报告
3. 级别分布校验：L0/L1/L2/L3 各级别数量一致
4. 模块级用例数校验：每个模块的用例数一致

**校验失败处理**：任何一项校验失败，评审直接判定为**不通过**。

### 步骤 3：执行完整性评审（含模板格式检查）

**检查清单**：

#### 3.1 章节完整性检查

- [ ] 所有功能模块（F-01, F-02, ...）都有测试分析
- [ ] 所有 API 接口都有测试点覆盖
- [ ] 每个模块都有 IBO 三维分析
- [ ] 报告四部分（1.1~4.4）章节齐全

#### 3.2 模板格式检查

**必需章节列表**（共 19 个章节）：
```
1.1, 1.2, 1.3, 1.4, 1.5, 2.1, 2.2, 3.1, 3.1.1, 3.1.2, 3.2, 3.3, 3.4, 3.5, 4.1, 4.2, 4.3, 4.4
```

**表格格式验证**：
- [ ] 1.1 插件基本信息表：表头为 `| 项目 | 内容 |`
- [ ] 1.4 功能模块一览表：表头为 `| 模块编号 | 功能名称 | 描述 | 优先级 |`
- [ ] 3.2 设备款型表：表头为 `| 设备款型 | 验证重点 |`
- [ ] 3.2 API 版本表：表头为 `| HarmonyOS 版本 | API Version | 验证重点 |`
- [ ] 3.2 交叉组合矩阵：表头为 `| 设备款型 | API 23 | API 22 | API 21 | API 19 | 其他 API |`
- [ ] 3.3 DFX 测试表：表头为 `| DFX 维度 | 测试重点 | 测试策略 |`
- [ ] 3.4 安全测试表：表头为 `| 安全维度 | 测试重点 | 测试策略 |`
- [ ] 3.1 各模块测试点表：表头为 `| 测试点编号 | 功能模块 | 测试点 | 验证点 | 覆盖 API | 测试点级别 |`

**IBO 分析格式验证**：
- [ ] 模块标题格式：`#### F-XX {模块名称} ({优先级})`
- [ ] IBO 分析使用 `- **Input（输入）**:`、`- **Behavior（行为）**:`、`- **Output（输出）**:` 格式
- [ ] 每个模块包含分析过程图/表（状态迁移图/判定表/边界值分析表）

> **详细检查清单**：见 `references/review-guide.md`「二、评审检查清单」

> **格式验证脚本**：`python scripts/verify_review_format.py <report_file_path>`

### 步骤 4：执行准确性评审

**检查清单**：
- [ ] IBO 输入分析准确识别参数类型
- [ ] IBO 行为分析准确识别行为特征
- [ ] IBO 输出分析准确识别返回值类型
- [ ] 测试方法与 IBO 特征匹配
- [ ] 测试点覆盖的 API 名称与需求解析一致
- [ ] 测试点级别符合 L0-L3 判定规则
- [ ] 模块优先级（P0/P1/P2）划分合理

> **详细检查清单**：见 `references/review-guide.md`「二、评审检查清单」

### 步骤 5：执行测试点质量评审

**检查清单**：
- [ ] 测试点描述使用黑盒功能视角，无 API 层面词汇
- [ ] 测试点描述具体，无模糊词汇
- [ ] 测试步骤清晰，测试人员可理解执行
- [ ] 验证点具体明确，有明确判定标准
- [ ] 无"功能执行正确，结果符合预期"等模糊描述
- [ ] 每个测试点标注了覆盖的 API
- [ ] 测试点编号规范（模块 ID+ 序号）

> **详细检查清单**：见 `references/review-guide.md`「二、评审检查清单」

### 步骤 6：执行兼容性评审

**检查清单**：
- [ ] 4 款型×4API 版本矩阵完整，必测/选测标识清晰
- [ ] 稳定性/性能/功耗/UX 四个维度均有测试策略
- [ ] 病毒扫描/开源漏洞/敏感信息三个维度均有测试策略
- [ ] 自动化可行性评估 + 覆盖率计算完整

> **详细检查清单**：见 `references/review-guide.md`「二、评审检查清单」

### 步骤 7：计算得分和通过状态

> **评分标准**：见 `references/review-guide.md`「三、评分标准」

> **通过标准**：见 `references/review-guide.md`「四、通过标准」

### 步骤 8：生成评审报告（含模板格式检查）

> **报告模板**：见 `assets/review-report-template.md`

#### 模板格式检查清单

**评审报告必须包含的章节**：
- [ ] 一、评审概述（评审维度及权重表）
- [ ] 二、三方比对校验结果（模块数、用例总数、级别分布）
- [ ] 三、评审结果汇总（五个维度得分表）
- [ ] 四、详细评审结果（完整性、准确性、测试点质量、兼容性）
- [ ] 五、修订建议（必须修订项、建议修订项）
- [ ] 六、评审结论

**评审报告表格格式**：
- [ ] 评审维度权重表：使用 `| 评审维度 | 权重 | 说明 |` 表头
- [ ] 三方比对表：使用 `| 来源 | 模块数 |` 或 `| 来源 | L0 | L1 | L2 | L3 |` 表头
- [ ] 评审结果汇总表：使用 `| 评审维度 | 得分 | 通过状态 |` 表头
- [ ] 详细评审表：使用 `| 检查项 | 状态 | 说明 |` 表头

**格式验证脚本**：
- 使用脚本验证：`python scripts/verify_review_format.py <review_report_file_path>`

## 校验失败处理

| 验证失败类型 | 处理措施 |
|--------------|----------|
| 模块数不一致 | 评审不通过，要求重新生成测试分析报告 |
| 用例总数不一致 | 评审不通过，要求重新生成测试分析报告 |
| 级别分布不一致 | 评审不通过，要求重新生成测试分析报告 |
| 模块级用例数不一致 | 评审不通过，要求重新生成测试分析报告 |

**否决规则**：三方比对任何一项不一致，评审直接判定为**不通过**。

---

## 评审结论

| 评审结论 | 条件 |
|---------|------|
| **通过** | 总体≥80 分 且 各维度均达标 且 三方比对 100% 一致 |
| **有条件通过** | 总体≥80 分 但有个别维度未达标，需完成必须修订项 |
| **不通过** | 总体<80 分 或 三方比对不一致 或 关键维度缺失 |
