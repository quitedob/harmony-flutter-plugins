# 分析过程可视化输出详解

## 概述

本文档提供 IBO 分析过程可视化输出的详细规范和完整示例。

---

## 分析过程输出类型

### 1. 状态迁移分析（适用于状态转换类模块）

**适用场景**：
- 模块涉及状态变化（如电话状态：待机→来电→通话中→通话结束）
- 模块有明确的状态枚举定义
- 行为依赖于当前状态

#### 状态迁移图

**绘图规范**：
- 使用 `[]` 包裹状态名称
- 使用 `→` 表示状态转换方向
- 在箭头上标注触发条件/事件
- 支持环路和分支

**示例**：
```
状态迁移图：

                    [来电事件]
    [NOTHING] ──────────────────→ [CALL_INCOMING]
       ↑  ↑                         │  │
       │  └─────────────────────────┘  │
       │         [挂断事件]            │
       └───────────────────────────────┘
                 [接通事件]
                    │
                    ▼
              [CALL_STARTED]
```

#### 状态迁移表

**填表规范**：
- 当前状态：迁移的起始状态
- 触发条件：触发迁移的事件/条件
- 下一状态：迁移后的目标状态
- 动作/输出：迁移时执行的动作或输出的事件

**示例**：

| 当前状态 | 触发条件 | 下一状态 | 动作/输出 |
|---------|---------|---------|----------|
| NOTHING | 来电事件 | CALL_INCOMING | 推送 CALL_INCOMING 事件 |
| CALL_INCOMING | 接通事件 | CALL_STARTED | 推送 CALL_STARTED 事件，启动计时器 |
| CALL_INCOMING | 挂断事件 | NOTHING | 推送 CALL_ENDED 事件 |
| CALL_STARTED | 挂断事件 | CALL_ENDED | 推送 CALL_ENDED 事件，停止计时器 |
| CALL_ENDED | - | NOTHING | 重置状态，准备下次监听 |

---

### 2. 判定表（适用于多条件组合模块）

**适用场景**：
- 模块行为依赖于多个条件的组合
- 不同条件组合产生不同的处理逻辑
- 需要验证所有条件组合的覆盖完整性

**填表规范**：
- 条件行：列出所有影响行为的条件
- 规则列：每一列代表一种条件组合
- 动作行：每种组合对应的处理动作
- 使用 `-` 表示该条件不影响此规则

**示例**：

| 条件/规则 | 规则 1 | 规则 2 | 规则 3 | 规则 4 |
|----------|-------|-------|-------|-------|
| 条件 1：READ_CALL_LOG 权限已授予 | Y | N | - | - |
| 条件 2：平台是 Android | Y | Y | N | N |
| 条件 3：对方隐藏号码 | N | N | Y | N |
| **动作** | 返回号码 | 返回 null | 返回 null | 返回 null |

> 注：Y=满足，N=不满足，-=不相关

---

### 3. 边界值分析（适用于数据计算模块）

**适用场景**：
- 模块涉及数值计算
- 有明确的边界定义（最小值、最大值）

**填表规范**：
- 测试场景：描述测试的业务场景
- 输入值：具体的输入数值
- 预期输出：期望的输出结果
- 边界类型：下边界/正常值/上边界/越界

**示例**：

| 测试场景 | 输入值（秒） | 预期输出 | 边界类型 |
|---------|-------------|---------|---------|
| 0 秒通话（立即挂断） | 0 | duration 为 0 或 null | 下边界 |
| 短时间通话（5 秒） | 5 | duration 为 5 秒 | 正常值 |
| 正常通话（3 分钟） | 180 | duration 为 180 秒 | 正常值 |
| 超长通话（24 小时） | 86400 | duration 为 86400 秒 | 上边界 |

---

### 4. 队列调度流程（适用于队列管理模块）

**适用场景**：
- 模块使用队列管理请求
- 多个请求需要按序处理
- 支持队列的添加、移除、清空操作

**绘图规范**：
- 使用 `[]` 包裹节点名称
- 使用 `→` 表示流程方向
- 标注关键操作步骤

**示例**：
```
队列调度流程图：

[请求 1] → [队列头部] → [正在处理] → [完成]
[请求 2] → [等待中]   ────────────────→ [待处理]
[请求 3] → [队列尾部] ────────────────→ [待处理]

添加请求：
[新请求] → [加入队列尾部] → [等待调度]

移除当前：
[当前显示] → [移除] → [队列头部成为新的当前]
```

## 分析过程输出决策树

```
模块行为特征是什么？
│
├─ 涉及状态变化？ → 输出【状态迁移图】和【状态迁移表】
├─ 依赖多个条件组合？ → 输出【判定表】
├─ 使用队列管理？ → 输出【队列调度流程图】
└─ 涉及数值计算？ → 输出【边界值分析表】
```

## 注意事项

1. **分析过程不是可选的**：每个模块必须根据其特征输出相应的分析过程图/表
2. **图文结合**：分析过程图/表后应配合文字说明，解释图表含义
3. **与测试点对应**：分析过程应能追溯到后续的测试点，测试点应覆盖分析中识别的所有场景
4. **格式统一**：使用统一的图形符号和表格格式，便于阅读理解
