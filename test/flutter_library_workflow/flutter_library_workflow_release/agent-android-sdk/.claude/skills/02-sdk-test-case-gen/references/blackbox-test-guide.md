# SDK 黑盒测试用例编写指南

## 概述

本指南指导如何将 SDK 测试点转化为黑盒测试用例。

**适用范围**：SDK 测试用例生成阶段

---

## 一、黑盒测试原则

### 1.1 纯黑盒视角

| ✅ 必须 | 测试步骤描述用户界面操作或功能行为 |
| ✅ 必须 | API 信息在步骤后的括号内备注 |
| ❌ 禁止 | 直接写 API 调用代码 |
| ❌ 禁止 | 使用"调用"、"访问"、"返回"等 API 层面词汇 |

### 1.2 示例对比

| 白盒/API 层面（错误） | 黑盒/功能层面（正确） |
|---------------------|---------------------|
| `调用 SDK.init(context)` | `点击【初始化】按钮 (API: SDK.init)` |
| `调用 getData() 方法获取数据` | `点击【获取数据】按钮 (API: getData)` |
| `设置 config.timeout 为 3000` | `在【超时时间】输入框中输入"3000" (API: config.timeout)` |
| `检查返回值是否为 true` | `验证【状态】文本显示"成功"` |
| `订阅 onResult 回调` | `点击【开始监听】按钮 (API: onResult)` |

---

## 二、SDK 测试用例特殊考量

### 2.1 HAR Demo 界面映射

SDK 测试用例基于 HAR Demo 应用的界面描述：

- **首页/入口页面**：展示各功能模块的导航按钮
- **模块页面**：每个功能模块有独立演示页面
- **结果面板**：显示 SDK API 调用结果的区域
- **操作按钮**：触发 SDK API 功能的按钮组

### 2.2 不同 SDK 类型的测试策略

| SDK 类型 | 测试模式 | 示例 |
|----------|---------|------|
| 平台交互类 | 授权 + 触发 + 观察结果 | 授权权限 → 点击功能按钮 → 观察结果面板 |
| 业务功能类 | 输入 + 执行 + 验证 | 输入参数 → 点击执行 → 验证结果 |
| 数据处理类 | 输入数据 + 处理 + 比对 | 输入原始数据 → 点击处理 → 验证输出数据 |
| UI 组件类 | 展示 + 交互 + 验证 | 点击展示 → 交互操作 → 验证 UI 状态 |
| 原生库类 | 调用桥接 + 验证结果 | 点击执行 → 等待结果 → 验证计算结果 |

## 三、测试用例结构

### 3.1 基本结构

| 字段 | 说明 | 示例 |
|------|------|------|
| 用例 ID | 模块 ID+ 序号 | F01-001 |
| 测试标题 | 测试内容概要 | 能正常初始化 SDK |
| 测试级别 | L0/L1/L2 | L0 |
| 前置条件 | 执行测试前的状态 | 应用已启动；SDK 已初始化 |
| 测试步骤 | 用户可执行的操作步骤 | 1. 在【配置】输入框中输入... 2. 点击【初始化】按钮 |
| 预期结果 | 明确的判定标准 | SDK 初始化成功，状态显示"已就绪" |
| 后置条件 | 测试执行后的状态 | 留空 |

---

## 四、测试用例级别判定

| 级别 | 说明 | 占比控制 |
|------|------|----------|
| L0 | 核心功能正常流程 | ≤30% |
| L1 | 其他正常流程 | ≤40% |
| L2 | 异常流程/边界值 | 剩余比例 |

**级别判定规则**：
- P0 核心功能正常流程 → L0
- P0 其他正常流程 → L1
- P0 异常/边界 → L2
- P1 最基础 1 个正常流程 → L0
- P1 其他正常流程 → L1
- P1 异常/边界 → L2

## 五、完整用例示例

### 5.1 平台交互类 SDK 示例（定位 SDK）

```
用例 ID: F01-001
测试标题：能正常获取当前位置信息
测试级别：L0
前置条件：应用已启动；已授予位置权限
测试步骤：
1. 点击【获取位置】按钮 (API: getCurrentLocation)
2. 等待 3 秒
3. 观察【位置信息】文本区域显示
预期结果：位置信息文本显示经纬度数据，格式正确
后置条件：""
```

### 5.2 数据处理类 SDK 示例（加密 SDK）

```
用例 ID: F02-001
测试标题：能正确加密文本数据
测试级别：L0
前置条件：应用已启动；功能界面已打开
测试步骤：
1. 在【输入文本】输入框中输入"Hello World"
2. 点击【加密】按钮 (API: encrypt)
3. 观察【加密结果】文本区域显示
预期结果：加密结果显示 Base64 编码的密文，非明文
后置条件：""
```

### 5.3 异常/错误场景 SDK 示例

```
用例 ID: F02-003
测试标题：验证使用无效参数时返回错误
测试级别：L2
前置条件：应用已启动
测试步骤：
1. 点击【Phrase 字符串模板引擎】进入模块列表页
2. 点击【验证无效 Key 格式】进入用例详情页
3. 在【模式字符串】输入框中输入"Hello {invalid key!}"
4. 点击【格式化】按钮
5. 观察【错误提示】文本区域显示
预期结果：错误提示区域显示错误信息，格式化操作未执行（以实际错误返回为准）
后置条件：""
```
