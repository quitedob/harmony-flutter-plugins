# SDK 测试分析 Skill

## 概述

基于 IBO 模型生成 SDK 测试点和测试分析报告的核心操作规范。

**适用范围**：SDK 测试分析阶段
**输入**：PRD 文件 + SDK 分析结果（01-analysis.json）
**输出**：测试分析报告（Markdown）、测试点汇总（JSON）

## 四、SDK 类型识别

针对 Android SDK 鸿蒙化适配，SDK 类型分类：

| SDK 类型 | 特征 | 测试重点 | 测试策略 |
|----------|------|----------|----------|
| **平台交互类** | 直接调用鸿蒙系统 API（蓝牙、相机、位置等） | 系统行为模拟、权限处理、回调机制 | 真机验证为主 |
| **业务功能类** | 封装业务逻辑（支付、分享、推送等） | 功能完整性、异常处理、数据一致性 | 功能验证 + 异常路径 |
| **数据处理类** | 数据处理、计算、编解码等 | 输入边界值、输出正确性、性能验证 | 边界值测试 + 对比验证 |
| **UI 组件类** | 提供可视化界面组件 | UI 渲染、交互响应、状态管理 | UI 自动化验证 |
| **原生库类** | 涉及 JNI/NAPI 桥接 | 桥接正确性、内存管理、线程安全 | 链路验证 + 稳定性测试 |

## 六、IBO 模型应用规范

### 6.1 测试方法选择

| IBO 维度 | 分析内容 | 测试方法 |
|---------|---------|---------|
| Input | 输入参数的类型和特征 | 等价类划分、边界值分析、空值测试 |
| Behavior | 功能行为的特征 | 状态迁移测试、判定表、并发测试 |
| Output | 输出数据的类型和特征 | 空集合测试、边界值分析、格式验证 |

### 6.2 测试点级别划分（三级制）

| 级别 | 定义 | 划分规则 |
|------|------|----------|
| L0 | 核心正常流程 | P0 正常流程 + P1/P2 核心正常流程 |
| L1 | 次要验证路径 | P0 异常/边界 + P1/P2 其他正常流程 |
| L2 | 边缘/异常路径 | P1/P2 异常/边界 |

**级别判定规则**：

| 模块优先级 | 测试类型 | 级别 |
|-----------|---------|------|
| P0 | 正常流程 | L0 |
| P0 | 异常流程/边界值 | L1 |
| P1 | 核心正常流程 | L0 |
| P1 | 其他正常流程 | L1 |
| P1 | 异常流程/边界值 | L2 |
| P2 | 核心正常流程 | L0 |
| P2 | 其他正常流程 | L1 |
| P2 | 异常流程/边界值 | L2 |

### 6.3 测试点数量控制（按优先级）

| 模块优先级 | 正常流程 | 异常流程 | 边界值 |
|-----------|---------|---------|--------|
| P0 | 全部生成 | 最多 2 个 | 最多 2 个 |
| P1 | 全部生成 | 最多 1 个 | 最多 1 个 |
| P2 | 全部生成 | 不生成 | 不生成 |

### 6.4 测试点聚焦原则（强制）

**核心规则**：每个测试点必须聚焦单一操作，避免一个测试点覆盖多个功能。

**拆分原则**：
1. **一个API = 一个测试点**：如果多个API独立完成不同功能，各自生成测试点
2. **一个操作 = 一个测试点**：如果用户需要执行多个独立操作，各自生成测试点
3. **一个验证目标 = 一个测试点**：每个测试点只验证一个具体的功能行为
4. **因果链合并例外!**：当 API 构成天然的因果链（"写后读/设置后查询/创建后验证"）且无法独立验证时，合并为一个测试点，步骤中包含完整序列（准备→操作→验证），用例名称以主操作为准。

**示例对比**：

| ❌ 合并写法（禁止） | ✅ 拆分写法（必须） |
|-------------------|-------------------|
| F-02-01: 查询有效路径的总空间、已用空间、可用空间 | F-02-01: 查询有效路径的总空间<br>F-02-02: 查询有效路径的可用空间<br>F-02-03: 查询有效路径的已用空间 |
| F-03-01: 创建对象并获取空间信息 | F-03-01: 创建存储卷对象<br>F-03-02: 获取存储卷总空间<br>F-03-03: 获取存储卷已用空间 |
| F-01-01: 获取路径列表并验证格式 | F-01-01: 获取设备存储卷路径列表<br>F-01-02: 验证路径列表格式正确 |

### 6.5 枚举值全覆盖原则（强制）

**核心规则**：当API参数包含枚举类型时，每个枚举值都必须有对应的测试点覆盖，确保正常流程验证全面。

**枚举值处理规则**：

| 枚举值数量 | 处理方式 | 示例 |
|-----------|---------|------|
| ≤5个 | 每个枚举值生成一个独立测试点 | Toast位置：TOP/CENTER/BOTTOM → 3个测试点 |
| 6-10个 | 按功能分组，每组生成测试点，核心值单独覆盖 | 优先级：P0/P1/P2/P3 → 4个测试点 |
| >10个 | 选择代表性值覆盖，说明选择理由 | ToastGravity 11个值 → 核心3个单独+其他分组 |

**枚举值测试点生成要求**：
1. **默认值必须覆盖**：枚举的默认值/最常见值优先生成测试点
2. **核心业务值必须覆盖**：与核心功能直接相关的枚举值必须单独生成测试点
3. **边界值可选覆盖**：极端场景的枚举值可合并或选测
4. **级别分配**：
   - 默认值/最常用值 → L0
   - 其他正常值 → L1
   - 边界/极端值 → L2

**示例对比**：

| 模块 | ❌ 错误做法（枚举合并） | ✅ 正确做法（枚举全覆盖） |
|------|---------------------|----------------------|
| Toast位置 | F-01-01: 验证Toast在不同位置显示 | F-01-01: 验证Toast在底部居中显示（默认）<br>F-01-02: 验证Toast在顶部居中显示<br>F-01-03: 验证Toast在屏幕中央显示 |
| Toast时长 | F-01-02: 验证不同时长Toast显示 | F-01-04: 验证短时长Toast显示（默认）<br>F-01-05: 验证长时长Toast显示 |
| 枚举分组 | F-03-01: 验证各种ToastGravity位置 | F-03-01: 验证BOTTOM位置（默认）<br>F-03-02: 验证TOP位置<br>F-03-03: 验证CENTER位置<br>F-03-04: 验证其他位置（合并测试） |

**禁止行为**：
- ❌ 将多个枚举值合并在一个测试点中（如"验证Toast在不同位置显示"）
- ❌ 遗漏枚举默认值的测试点
- ❌ 遗漏核心业务场景的枚举值测试点

**允许行为**：
- ✅ 枚举值>10个时，选择代表性值覆盖并说明理由
- ✅ 非核心枚举值可分组测试（如"验证其他位置"）

**禁止行为**（测试点聚焦）：
- ❌ 一个测试点包含多个独立API的验证
- ❌ 一个测试点包含多个用户操作步骤
- ❌ 一个测试点验证多个不相关的功能行为

**允许行为**（测试点聚焦）：
- ✅ 一个测试点包含前置条件检查（如"设备存储卷可用"）
- ✅ 一个测试点包含关联验证（如"查询总空间后验证数值大于0"）
- ✅ 一个测试点包含因果关系验证（如"总空间 = 已用 + 可用"）

**需要生成异常/边界的条件**（必须同时满足）：
1. 模块优先级为 P0 或 P1
2. 模块 API 有明确的参数输入验证（如路径、数值、空值）
3. 模块涉及资源管理（如存储空间、内存、连接数）
4. 模块有明确的状态转换和错误处理

**禁止生成异常/边界的情况**：
- ❌ 模块仅做简单数据查询/封装，无异常可测
- ❌ 模块的异常处理已在其他模块覆盖
- ❌ 模块功能单一，无明显边界条件
- ❌ P2 优先级模块

## 七、黑盒视角检查清单

### 7.1 API 词汇检查

- [ ] 测试点名称不包含：调用、访问、返回、注册、创建、设置、传入、执行、加载
- [ ] 测试点描述不包含"调用 XX 方法"、"传入 XX 参数"

### 7.2 验证点具体性检查

- [ ] 验证点不包含"功能执行正确，结果符合预期"等模糊描述
- [ ] 验证点具体明确，可执行、可判定

### 7.3 功能视角检查

- [ ] 测试点从用户/功能视角描述，而非 API 调用视角
- [ ] 聚焦于用户可感知的功能行为

**评分规则**（自评审使用）：
- 每个 API 词汇使用：-5 分
- 每个模糊验证点：-3 分
- 每个非功能视角测试点：-5 分
- 基础分 100 分，扣分后≥90 分为通过

### 7.4 平台无关性检查

- [ ] 测试点名称、描述、验证点中无"Android"、"Java"、"Kotlin"等平台特定词汇
- [ ] 无源平台特有 API 名称（如"BLUETOOTH_CONNECT"、"Activity"）
- [ ] 无源平台特有版本号（如"Android 12+"）
- [ ] 权限描述使用鸿蒙平台通用术语（如"蓝牙连接权限"而非"BLUETOOTH_CONNECT"）

**转化规则**：

| 源描述（错误） | 转化后（正确） |
|--------------|--------------|
| "Android 12+ 新权限模型行为" | "鸿蒙权限模型行为"或"新版权限模型行为" |
| "正确处理 BLUETOOTH_CONNECT 权限请求" | "正确处理蓝牙连接权限请求" |
| "如'Android 13'" | "如'HarmonyOS NEXT'"或"如'API 23'" |
| "Android 端来电时 number 字段显示具体号码" | "来电时 number 字段显示具体号码（需鸿蒙系统支持）" |
