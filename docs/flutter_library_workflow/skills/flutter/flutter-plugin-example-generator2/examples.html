Flutter 插件 Example 规则示例

示例 1：三级导航结构

  • 一级页面：接口总览页（路由：/api-index）
    • 列出 showToast、cancel 等所有对外接口
  • 二级页面：showToast 接口测试列表页（路由：/api/showToast/cases）
    • 列出 TC_TOAST_01、TC_TOAST_02、TC_TOAST_03 ...
  • 三级页面：TC_TOAST_01 单用例页（路由：/api/showToast/case/TC_TOAST_01）
    • 仅执行一个动作并输出结果

示例 2：单用例页面模板（4 区块）

  1. 测试说明区
    • 目标：验证 short toast
    • 前置：已进入该用例页
  2. 操作区
    • 按钮：btn_case_TC_TOAST_01_run
  3. 结果区
    • txt_status
    • txt_result
  4. 返回区
    • 按钮：btn_back

示例 3：接口到用例映射

输入 API：

  • showToast(...)
  • cancel()

映射：

  • 一级：item_api_showToast
    • 二级：/api/showToast/cases + item_case_TC_TOAST_01 -> 三级：/api/showToast/case/TC_TOAST_01
    • 二级：/api/showToast/cases + item_case_TC_TOAST_02 -> 三级：/api/showToast/case/TC_TOAST_02
  • 一级：item_api_cancel
    • 二级：/api/cancel/cases + item_case_TC_TOAST_07 -> 三级：/api/cancel/case/TC_TOAST_07

示例 4：README 矩阵片段

| 接口 | 用例项 ID | 用例页面路由 | 执行按钮 ID | 断言 |
|---|---|---|---|---|
| showToast | item_case_TC_TOAST_01 | /api/showToast/case/TC_TOAST_01 | btn_case_TC_TOAST_01_run | txt_result 前缀 |
| showToast | item_case_TC_TOAST_03 | /api/showToast/case/TC_TOAST_03 | btn_case_TC_TOAST_03_run | txt_result 前缀 |
| cancel | item_case_TC_TOAST_07 | /api/cancel/case/TC_TOAST_07 | btn_case_TC_TOAST_07_run | txt_result 前缀 |

示例 5：好坏对比

坏例子：

  • 一个页面放多个用例按钮，并共用一个复杂状态区域。

好例子：

  • 一用例一页面；
  • 一按钮一原子动作；
  • 结果输出固定为 txt_status 与 txt_result；
  • 明确返回上一级路径。

示例 6：平台无关接口

接口 formatMessage() 为纯 Dart 逻辑，不走 channel，不调用平台能力。

  • 一级页面：/api-index 仍展示 item_api_formatMessage
  • 二级页面：/api/formatMessage/cases 展示说明：
    • “该接口与平台无关，无需平台能力用例”
  • 三级页面：可不生成
