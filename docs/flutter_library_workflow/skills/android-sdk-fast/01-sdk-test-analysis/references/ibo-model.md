# IBO 模型详解

## 概述

IBO（Input-Behavior-Output）模型是测试分析的核心方法论，用于对每个功能模块进行结构化测试分析。

## 模型定义

| 维度 | 含义 | 分析内容 | 测试方法 |
|------|------|----------|----------|
| Input | 输入 | 输入参数的类型和特征 | 等价类划分、边界值分析、空值测试 |
| Behavior | 行为 | 功能行为的特征 | 状态迁移测试、判定表、并发测试 |
| Output | 输出 | 输出数据的类型和特征 | 空集合测试、边界值分析、格式验证 |

## 分析流程

1. **识别输入特征** → 选择输入测试方法
2. **识别行为特征** → 选择行为测试方法
3. **识别输出特征** → 选择输出测试方法
4. **生成功能点** → 标注级别（L0/L1/L2）

> **粒度说明**：分析的最小绑定单位是**功能点（FeaturePoint）**，而非单个 API。一个功能点 = 一个用户可感知的单一能力 / 单一验证目标，**可由多个协同 API 共同实现**，不按 API 个数拆分。一个功能点对应一个测试用例（1:1），用例 ID 采用 `F-01-01` 格式。功能点在 Android 上由 `coveredApis.android` 记录其实现 API（可多个），HarmonyOS 实现可能由不同的 API 集合达成（设计期 `coveredApis.harmony` 留空，由下游回填）。

## 输入特征分类

| 特征类型 | 说明 | 示例 | 适用测试方法 |
|----------|------|------|-------------|
| 必填参数 | 不可为空的输入 | 用户ID、配置项 | 空值测试、边界值 |
| 可选参数 | 可以省略的输入 | 超时时间、默认值 | 等价类划分（有/无） |
| 枚举参数 | 有限取值集合 | 状态类型、操作类型 | 等价类划分（每个枚举值） |
| 数值参数 | 连续/离散数值 | 大小、数量、索引 | 边界值分析 |
| 对象参数 | 复合数据结构 | 配置对象、请求体 | 等价类划分（字段组合） |
| 集合参数 | 列表/数组 | 数据列表、ID 列表 | 边界值（空、1、多）、顺序 |

## 行为特征分类

| 特征类型 | 说明 | 适用测试方法 |
|----------|------|-------------|
| 状态转换 | 有明确状态机 | 状态迁移测试 |
| 条件组合 | 多条件判定 | 判定表/因果图 |
| 顺序依赖 | 操作顺序影响结果 | 场景测试 |
| 并发行为 | 多线程/异步操作 | 并发测试、竞态测试 |
| 副作用 | 操作有持久影响 | 副作用验证 |
| 幂等性 | 重复调用结果一致 | 幂等性测试 |

## 输出特征分类

| 特征类型 | 说明 | 适用测试方法 |
|----------|------|-------------|
| 返回值 | 方法返回数据 | 返回值验证 |
| 回调通知 | 异步结果通知 | 回调验证 |
| 状态变化 | 数据/状态更新 | 前后对比验证 |
| 副作用 | 间接影响 | 副作用验证 |

## 功能点生成原则

1. 每个 IBO 维度至少生成 1 个功能点
2. 一个功能点 = 一个单一能力 / 单一验证目标，**不按 API 个数拆分**；多个协同 API 实现同一能力时合并为同一个功能点，并把这些 API 一并写入 `coveredApis.android`
3. 枚举值全覆盖时，按 **scenario** 拆分：同一能力的不同 scenario（normal / exception / boundary）各对应一个功能点
4. P0 模块：正常流程全部覆盖，异常/边界最多各 2 个
5. P1 模块：正常流程全部覆盖，异常/边界最多各 1 个
6. P2 模块：只覆盖正常流程

## 功能点拆分示例（Toast 能力）

以「显示 Toast 提示」能力为例，说明**按功能点而非按 API 拆分**的粒度。

假设 Android 侧由多个协同 API 共同实现一次完整的 Toast 展示：`Toast.makeText(...)`、`setDuration(...)`、`show()`。这三个 API 协同完成「弹出一条提示并按时长消失」这一个用户可感知能力，因此**合并为一个功能点**，而不是拆成三个：

| 用例编号 | 功能点（featureName） | scenario | 级别 | coveredApis.android |
|----------|----------------------|----------|------|---------------------|
| F-01-01 | 正常时长内显示并自动消失的 Toast 提示 | normal | L0 | `Toast.makeText`, `setDuration`, `show` |
| F-01-02 | 空文本 / 超长文本时的 Toast 提示 | boundary | L1 | `Toast.makeText`, `show` |
| F-01-03 | 非主线程调用 Toast 时的异常处理 | exception | L2 | `Toast.makeText`, `show` |

对于**枚举值全覆盖**（如 Toast 时长枚举 `LENGTH_SHORT` / `LENGTH_LONG`），不为每个枚举值各建一个功能点，而是表达为「同一能力在不同 scenario 下的验证」——常用枚举归入 normal 功能点的等价类覆盖，越界 / 非法枚举值归入 boundary 或 exception 功能点。

> 关键点：API 是功能点的**分平台元数据**。同一个「显示 Toast」功能点，在 HarmonyOS 上可能由 `promptAction.showToast` 等完全不同的 API 集合实现，无法与 Android API 一一映射，因此用例绑定到功能点而非 API，`coveredApis.harmony` 在设计期留空由下游回填。
