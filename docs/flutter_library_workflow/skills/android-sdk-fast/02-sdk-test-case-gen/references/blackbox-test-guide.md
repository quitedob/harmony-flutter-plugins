# SDK 黑盒测试用例编写指南

## 概述

本指南指导如何将 SDK 功能点转化为黑盒测试用例。

**适用范围**：SDK 测试用例生成阶段

**核心模型**：模块 1──N 功能点 1──1 测试用例（用例 `id == featurePointId`）。一个功能点 = 一个用户可感知能力 / 单一验证目标，可由多个协同 API 实现。**每个功能点转化为一条测试用例（1:1）**。API 信息不写入步骤，统一记入用例级 `coveredApis.android`。

---

## 一、黑盒测试原则

### 1.1 纯黑盒视角

| ✅ 必须 | 测试步骤描述用户界面操作或功能行为 |
| ✅ 必须 | 步骤只写平台无关的功能语义；API 信息不写入步骤，记入用例级 `coveredApis.android` |
| ❌ 禁止 | 直接写 API 调用代码 |
| ❌ 禁止 | 步骤内出现 API 名，或追加 `(API: methodName)` 备注 |
| ❌ 禁止 | 使用"调用"、"访问"、"返回"等 API 层面词汇 |

> **为何步骤内不写 API**：同一功能点在 Android 与 HarmonyOS 上 API 集合不同，无法一一映射。把 API 烤进步骤会让用例绑死 Android API。改为 `coveredApis` 元数据后，步骤是平台无关的功能语义，鸿蒙无论用什么 API 实现都适用。

### 1.2 示例对比

下列「正确」列步骤均为纯功能语义、不含 API 名；对应 API 记入用例级 `coveredApis.android`。

| 白盒/API 层面（错误） | 黑盒/功能层面（正确，步骤无 API） | 记入 coveredApis.android |
|---------------------|---------------------|---------------------|
| `调用 SDK.init(context)` | `点击【初始化】按钮` | `["SDK.init"]` |
| `调用 getData() 方法获取数据` | `点击【获取数据】按钮` | `["getData"]` |
| `设置 config.timeout 为 3000` | `在【超时时间】输入框中输入"3000"` | `["config.timeout"]` |
| `检查返回值是否为 true` | `验证【状态】文本显示"成功"` | （归并到本功能点其他 API） |
| `订阅 onResult 回调` | `点击【开始监听】按钮` | `["onResult"]` |

## 二、SDK 测试用例特殊考量

### 2.1 HAR Demo 界面映射

SDK 测试用例基于 HAR Demo 应用的界面描述：

- **首页/入口页面**：展示各功能模块的导航按钮
- **模块页面**：每个功能模块有独立演示页面
- **结果面板**：显示 SDK API 调用结果的区域
- **操作按钮**：触发 SDK API 功能的按钮组

### 2.2 不同 SDK 类型的测试策略

| SDK 类型 | 测试模式 | 示例 |
|----------|---------|------|
| 平台交互类 | 授权 + 触发 + 观察结果 | 授权权限 → 点击功能按钮 → 观察结果面板 |
| 业务功能类 | 输入 + 执行 + 验证 | 输入参数 → 点击执行 → 验证结果 |
| 数据处理类 | 输入数据 + 处理 + 比对 | 输入原始数据 → 点击处理 → 验证输出数据 |
| UI 组件类 | 展示 + 交互 + 验证 | 点击展示 → 交互操作 → 验证 UI 状态 |
| 原生库类 | 调用桥接 + 验证结果 | 点击执行 → 等待结果 → 验证计算结果 |

## 三、测试用例结构

### 3.1 基本结构

| 字段 | 说明 | 示例 |
|------|------|------|
| 用例 ID | 统一 `F-01-01` 格式（模块号-用例序号） | F-01-01 |
| featurePointId | 对应功能点 ID，**必须等于用例 ID** | F-01-01 |
| 测试标题 | 测试内容概要 | 能正常初始化 SDK |
| 测试级别 | L0/L1/L2 | L0 |
| coveredApis | `{android:[...],harmony:[]}`，本功能点所用全部 API 记入 android，harmony 留空 | `{"android":["SDK.init"],"harmony":[]}` |
| 前置条件 | 统一为"应用已启动" | 应用已启动 |
| 测试步骤 | 用户可执行的操作步骤，只写功能语义、无 API 名；固定前两步为模块列表页 + 用例详情页导航 | 1. 点击【加密】进入模块列表页 2. 点击【能正常初始化 SDK】进入用例详情页 3. 点击【初始化】按钮 |
| 预期结果 | 明确的判定标准 | SDK 初始化成功，状态显示"已就绪" |
| 后置条件 | 测试执行后的状态 | 留空 |

## 四、测试用例级别判定

| 级别 | 说明 | 占比控制 |
|------|------|----------|
| L0 | 核心功能正常流程 | ≤30% |
| L1 | 其他正常流程 | ≤40% |
| L2 | 异常流程/边界值 | 剩余比例 |

**级别判定规则**：
- P0 核心功能正常流程 → L0
- P0 其他正常流程 → L1
- P0 异常/边界 → L2
- P1 最基础 1 个正常流程 → L0
- P1 其他正常流程 → L1
- P1 异常/边界 → L2

## 五、完整用例示例

> 所有示例步骤均为纯功能语义、不含 API 名；API 统一记入 `coveredApis.android`。固定前两步为模块列表页 + 用例详情页导航。

### 5.1 平台交互类 SDK 示例（定位 SDK）

```
用例 ID: F-01-01
featurePointId: F-01-01
测试标题：能正常获取当前位置信息
测试级别：L0
coveredApis: {"android": ["getCurrentLocation"], "harmony": []}
前置条件：应用已启动
测试步骤：
1. 点击【定位】进入模块列表页
2. 点击【能正常获取当前位置信息】进入用例详情页
3. 点击【获取位置】按钮
4. 等待 3 秒
5. 观察【位置信息】文本区域显示
预期结果：位置信息文本显示经纬度数据，格式正确
后置条件：""
```

### 5.2 数据处理类 SDK 示例（加密 SDK）

```
用例 ID: F-02-01
featurePointId: F-02-01
测试标题：能正确加密文本数据
测试级别：L0
coveredApis: {"android": ["encrypt"], "harmony": []}
前置条件：应用已启动
测试步骤：
1. 点击【加密】进入模块列表页
2. 点击【能正确加密文本数据】进入用例详情页
3. 在【输入文本】输入框中输入"Hello World"
4. 点击【加密】按钮
5. 观察【加密结果】文本区域显示
预期结果：加密结果显示 Base64 编码的密文，非明文
后置条件：""
```

### 5.3 多 API 协同功能点示例（一个功能点多步骤）

功能点「显示下载进度」由 `setMax` + `setProgress` 协同实现，对应一条用例的多个步骤，API 全部归入 `coveredApis.android`：

```
用例 ID: F-03-01
featurePointId: F-03-01
测试标题：能正确显示下载进度
测试级别：L1
coveredApis: {"android": ["setMax", "setProgress"], "harmony": []}
前置条件：应用已启动
测试步骤：
1. 点击【下载】进入模块列表页
2. 点击【能正确显示下载进度】进入用例详情页
3. 设置进度上限为 100
4. 将进度设置为 50%
5. 观察【进度条】显示 50%
预期结果：进度条停在 50% 位置，进度文本显示"50%"
后置条件：""
```

### 5.4 异常/错误场景 SDK 示例

```
用例 ID: F-02-03
featurePointId: F-02-03
测试标题：验证使用无效参数时返回错误
测试级别：L2
coveredApis: {"android": ["format"], "harmony": []}
前置条件：应用已启动
测试步骤：
1. 点击【Phrase 字符串模板引擎】进入模块列表页
2. 点击【验证无效 Key 格式】进入用例详情页
3. 在【模式字符串】输入框中输入"Hello {invalid key!}"
4. 点击【格式化】按钮
5. 观察【错误提示】文本区域显示
预期结果：错误提示区域显示错误信息，格式化操作未执行（以实际错误返回为准）
后置条件：""
```
